# 4th & Inches — league site

Static site for the league. No build step — plain HTML/CSS/JS, served
as-is by GitHub Pages. Live at `https://4thNInches.github.io/`.

## How it's put together

The site has two layers of data:

1. **Historical (2015–2025, Yahoo era)** — baked into static JSON files
   in `data/`, generated by a set of local Python scripts. You only rerun
   these when something historical needs fixing, or once a year when a
   completed Sleeper season needs folding into history.
2. **Current season (2026+, Sleeper)** — fetched live, in the browser,
   on every page load. Standings and Lifetime Standings both merge this
   in real time; nothing needs to be regenerated week to week for those
   to update.

## Files

- `index.html`, `style.css`, `script.js` — the site itself
- `assets/logo.png` — league logo (referenced in the header; if it's
  missing, the site just hides that spot, nothing breaks)
- `data/` — see below

## Data files (`data/`)

| File | What it's for | How it's produced |
|---|---|---|
| `champions.json` | Top-3 finishers per season, 2015–2025 | **Manually maintained** — hand-typed from Yahoo's standings screenshots. Not script-generated; needs a manual edit when a new season completes. |
| `facts.json` | Random league facts for the ticker | `generate_facts.py` |
| `stat_cards.json` | The 4 League Stats cards (highest scores, closest margins, win streaks, championships) | `generate_stat_cards.py` |
| `lifetime_standings.json` | Career stats per manager through 2025, before the live Sleeper merge | `generate_lifetime_standings.py` |
| `sleeper_manager_mapping.json` | Maps Sleeper display names → manager ids, so the live site can match this year's rosters to career history | Copied automatically by `generate_lifetime_standings.py` from its local counterpart (see below) |

All five need to exist in `data/` for the site to be fully populated;
each loader on the page fails gracefully (shows a message, doesn't break
the rest of the page) if one is missing.

## The Python pipeline (run locally, not part of the deployed site)

These scripts aren't part of what GitHub Pages serves — they're local
tooling that produces the JSON files above. Typical layout:

```
data/history/<year>.json   # one file per season, 2015-2025
manager_mapping.json       # team name -> manager id (handles team renames)
managers.json              # manager id -> display name, seasons played, etc.
sleeper_manager_mapping.json  # Sleeper display name -> manager id (local copy)
```

**Requirements:** `pip install requests beautifulsoup4`

### One-time / rare: historical export

`export_yahoo_history.py` scrapes Yahoo for full season history (schedules
+ playoff brackets) into `data/history/<year>.json`. You already have all
11 seasons (2015–2025) — you shouldn't need to touch this again until
2026 completes and you want to add it to history the same way.

2015–2019 need a Yahoo session cookie (those leagues aren't public):
set `YAHOO_COOKIE` or drop it in `yahoo_cookies.txt` next to the script.
It expires periodically — if a run starts failing with a "looks like a
login page" error, grab a fresh one (see the script's docstring for the
exact steps) and rerun. Each season writes its own file, so a rerun only
needs to redo whatever failed.

Playoff brackets are parsed directly from
`https://football.fantasysports.yahoo.com/league/<slug>/<year>` (explicit
winner/loser markers in the page, not inferred from scores) — this is the
reliable path; an earlier approach that reconstructed brackets from
individual matchup pages turned out to hit genuinely inconsistent data
from Yahoo and was scrapped.

### Regenerate after any historical data change

```
python3 generate_stat_cards.py
python3 generate_lifetime_standings.py
```

`generate_lifetime_standings.py` also needs `managers.json` and
`manager_mapping.json` to exist, and needs `sleeper_manager_mapping.json`
filled in — if that file doesn't exist yet, running the script once will
fetch your current Sleeper league's member list and write a template for
you to fill in (map each Sleeper display name to the matching id from
`managers.json`), then rerun.

Both scripts print their full output to the terminal — worth a skim for
anything that looks off before copying the result into `data/`.

### What's NOT a script

`champions.json` is hand-maintained (see table above). If you want that
automated eventually, that's a reasonable follow-up project, but it isn't
built yet.

## Getting it live on GitHub Pages

Since your GitHub username is `4thNInches`, the clean URL
(`4thandinches.github.io`) isn't available to you directly — GitHub Pages
user sites have to live in a repo named exactly `<username>.github.io`.

**Current setup: user site at `4thNInches.github.io`**
1. Repo named exactly `4thNInches.github.io`, files at the repo root.
2. Repo **Settings → Pages**: source = "Deploy from a branch," branch
   `main`, folder `/ (root)`.
3. Live at `https://4thNInches.github.io/`.

If you ever move to a custom domain, update the `og:image`/`og:url` meta
tags in `index.html`'s `<head>` to match — they're currently hardcoded to
the URL above for link-preview purposes (sharing the site link in a chat
shows a proper title/description/logo card instead of a bare link).

## Local preview

No server needed for a quick look — just open `index.html` in a browser.
But since the site does real `fetch()` calls (to its own `data/*.json`
files and to Sleeper's API), opening it directly as a `file://` URL will
fail those fetches silently in most browsers. For anything beyond a
glance, run a local server instead:

```
python3 -m http.server 8000
```

Then visit `http://localhost:8000`.

## Known gaps / possible next steps

- `champions.json` isn't automated (see above).
- The live Sleeper merge (Lifetime Standings, current-season Standings)
  deliberately stops before this season's playoff weeks, to stay
  consistent with the historical data being regular-season-only. Once
  2026's playoffs happen, the Playoff Rec / Playoff Seasons columns won't
  pick them up automatically — that needs a Python re-run once 2026 gets
  added to `data/history/`, not a live fix.
- No favicon set yet.
- Sortable tables (Standings, Lifetime Standings) aren't keyboard
  accessible yet — click-only, no Tab/Enter support.
